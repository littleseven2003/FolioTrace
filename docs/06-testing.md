# 测试与验收

启动包检查只是 M0 门槛。M1 起使用 Vitest 测纯领域函数与服务；React Testing Library 测用户交互；桌面自动化在确认 Electron 版本兼容后用 Playwright，macOS 原生打开文件保留手工测试。

## 必测矩阵

| 层 | 场景 | 期待 |
| --- | --- | --- |
| 路径 | ../、绝对路径、UNC、盘符、symlink、写入时父目录变化 | 拒绝，根外不读写 |
| 导入 | 同事件两次；同 ID 不同内容 | 一次成功；冲突拒绝 |
| 事务 | 2 个产出中第 2 个缺文件 | 0 个被导入，revision 不变 |
| 版本 | 跨材料父版、循环、未知父版 | 拒绝 |
| 关系 | 配套到旧版后改“当前采用” | 原端点不变 |
| 指纹 | 任务参考文件被替换、历史输出原地编辑 | 待处理，旧 sha 不改 |
| 故障 | 快照 rename 前后崩溃、投影生成失败 | 旧或新完整快照，无半提交，可重建投影 |
| 并发 | 两实例写、同 revision 更新 | 单写锁或 revision 冲突，不能丢更新 |
| 状态 | Agent 新版导入 | candidate；不自动 current |
| 分类 | 新文件/排除文件 | 不默认加入参考 |
| UI | 键盘、长文件名、无项目、空版本、权限拒绝 | 可理解且可恢复 |
| 扫描 | 关闭应用期间文件改变，再打开 | 全量对账发现变化 |

## 目录视图与多文件版本验收

下列 M2 行已由自动测试覆盖（目录树 9 个、视图状态 2 个、交互 7 个）；M3 起行为后续目标，尚未实现。

| 阶段 | 场景 | 期待 |
| --- | --- | --- |
| M2 | MD 与 images/figures/media 下大量资源、混合用途目录 | 默认折叠，计数准确；展开不改用途、ID、指纹或 revision |
| M2 | 目录/平铺切换、完整路径搜索、清除搜索、刷新 | 分类控件仍可用；命中祖先临时展开；清空搜索恢复折叠状态 |
| M2 | 中文长路径、重复文件名、空清单、无匹配、键盘 | 正确定位文件；按钮焦点与 aria-expanded 正确；错误/警告不丢失 |
| M3 | v1 单文件项目升级 | 备份与受保护迁移；保留 ID、旧指纹、父版、采用、配套、账本；失败无半迁移 |
| M3 | MD 加图片，PPT 加音乐/视频，目录内多类型 | 用户确认后登记一个版本；可选入口在清单内；媒体内嵌的 Office 仍为单文件 |
| M3 | 只修改图片/音视频；新增或删除目录成员 | 影响版本状态，不改旧清单与指纹；新增文件不自动回填旧版 |
| M3 | 共享资源被覆盖、多版资源缺失、无入口 | 各受影响版本提示 drift/missing；不承诺哈希恢复；无入口只展示清单 |
| M3–M5 | images 名称、根外图片链接、远程 URL、符号链接、清单中一项失败 | 不自动推断或联网，不越界；多成员登记/导入全有或全无 |
| M4–M5 | 任务/回交含多文件版本 | 固定获准成员路径与指纹，旧事件兼容策略明确，不能只校验主文件 |

## 合成样例验收

把 examples/demo-project 复制到临时业务目录，勿直接改仓库 fixture。初始 revision=1，PPT 对应的 Markdown 材料 doc-slides 使用 v-slides-1；报告 v-report-1 配套它。导入 event-demo-001 后增加 v-slides-2，仍采用 v-slides-1；再导入无变化。用户采用 v-slides-2 后，报告仍对应 v-slides-1，应提示核对配套。

## 手工桌面路径

开目录 -> 分类 -> 版本登记 -> 任务生成 -> 在外部 Agent 生成记录 -> 待处理/导入 -> 查看图谱 -> 设为采用 -> 退出重启。验证每一步的实际磁盘文件，而不是仅截图。

## M1 当前自动覆盖

- 领域：版本按生成时间排序、最新生成与当前采用相互独立、未知版本处理、MockRepository 快照隔离。
- 交互：三份材料卡、材料切换、版本选择、徽标语义、占位页面、Result 失败与错误重试、内部异常不泄漏堆栈。
- IPC：Result 成功/失败、仓库异常脱敏、其他窗口/子框架/非入口 URL 被拒绝、生产入口与开发服务器来源校验。
- M2 扫描：真实临时目录只读扫描、内部目录忽略、符号链接越界、权限警告、扫描期间文件消失竞态、业务文件哈希前后一致、目录授权与 handle 校验。
- M2 目录替换：子目录、祖先目录、根目录及文件元数据阶段被替换时整次扫描终止，返回 `SCAN_ABORTED`，不返回任何根外文件。
- M2 元数据：初始化/重复初始化不覆盖、重新打开保留原有 ID/分类、损坏 JSON 与不支持 schemaVersion、活动锁、写入失败、revision 冲突、管理目录/目标文件符号链接拒绝、业务原文件哈希不变、现有 schema fixture 校验。
- M2 文件用途分类：真实临时目录与真实元数据存储；首次登记校验真实 SHA-256 与稳定 ID，重复修改保留 ID/指纹及 documents 等关联数据，内容漂移保留旧指纹并标记 `contentChanged`，未初始化拒绝且不创建 `.docwork`，越界/内部目录/符号链接/目录拒绝，expectedRevision 冲突不覆盖，授权根替换返回 `ROOT_IDENTITY_MISMATCH`；IPC handler 覆盖 handle/来源校验；交互覆盖用途保存、未初始化只读、重新扫描保留用途、冲突提示重新读取、内容漂移提示。
- M2 目录视图：由合成扫描结果覆盖根下文件、多层 images/figures/media、同名不同路径、长中文路径、折叠/展开、平铺切换、完整路径搜索/清除、无匹配、刷新保留与目录消失、键盘 Enter/Space 与 `aria-expanded`；交互测试断言展开、搜索、切换视图不调用分类写接口，展开后用途仍正确且可保存；搜索期间目录行 `aria-expanded`/箭头与可见行一致、折叠被禁用，点击目录不改变清除搜索后的恢复状态。
- M2 IPC handler：只 mock Electron 运行时，使用真实授权表、元数据存储与临时目录；`files:scan` 已授权 handle 返回真实相对文件，未知 handle 与绝对路径均返回 `PROJECT_NOT_FOUND`，其他窗口/子框架/非入口 URL 返回 `UNTRUSTED_SOURCE`，`project:initialize` 在授权根被替换后仍返回 `ROOT_IDENTITY_MISMATCH`。
- M2 授权根身份：根目录被移走并换成根外符号链接、根目录换成另一普通目录、祖先目录被替换时拒绝；回归测试比较根外目录与迁移前目录的完整内容哈希，并断言未创建 `.docwork`。
- 尚未自动覆盖：原生目录选择器的真实系统对话框点击（窗口验收通过 stub 触发）、Playwright 桌面 E2E、多文件版本与版本成员清单、自动恢复最近项目、导入事务与崩溃恢复；单次系统调用边界内瞬时替换并恢复的极端竞态无法用路径级测试完全覆盖。

## GitHub CI

ci.yml 现在执行 `npm ci`，再运行 `npm run check`（启动包检查、typecheck、lint、测试、build）以及新提交与 PR 标题校验；CI 不启动 Electron 窗口，因此跳过 Electron 二进制下载。M6 增加 macOS 构建；未验证平台不宣称支持。禁止为了绿色状态删掉失败测试或使用 continue-on-error。
