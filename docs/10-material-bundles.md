# 材料、版本与配套资源设计

决策日期：2026-10-21。状态：产品方向已确认；M2 展示层目录浏览与路径搜索已实现，多文件版本待 M3 实现。

## 当前实现与设计边界

当前软件 0.0.0、schemaVersion=1。M2 已实现文件扫描、初始化和逐文件用途保存；磁盘目录未重排。当前协议仍是 Version.fileId + SHA-256 的单文件版本。本说明不授权将新字段写入 v1 项目，也不表示原型或程序已经支持材料包。

M2 已增加纯展示层目录折叠、平铺切换与路径搜索，不写版本成员；之后收尾 M2。M3 开始前完成多文件协议设计与迁移验收，再实现材料和版本。近期不将批量分类、重命名迁移或自动恢复最近项目作为 M2 的新增合并门槛。

## 三个独立维度

| 维度 | 含义 | 规则 |
| --- | --- | --- |
| 文件用途 role | 参考 / 过程 / 产出 / 排除 / 未分类 | 保留现有五种，不增加 asset 作为第六种用途 |
| 版本内归属 | 某个版本的入口、资源或附件 | 归属固定到 versionId；不按文件夹名或用途自动建立 |
| 文件类型 | MD、DOCX、PPTX、图片、音频、视频等 | 用于展示和打开，不决定材料分组或用途 |

普通目录只是物理容器，可能混有多种用途、不同材料及不同版本。折叠目录不等于排除文件；将文件加入某版本也不能自动改写它的用途。参考图片可以是 reference，报告插图可以是 output 或用户另行指定的用途。成员在任务中是否可读，仍须检查任务授权与排除状态；所属材料为产出不代表其中所有成员都获准参考。

## 同一材料允许三种版本形式

| 形式 | 示例 | 展示 |
| --- | --- | --- |
| 单文件 | 内嵌资源的 Word/PPT、独立 Markdown | 一个版本、一份文件 |
| 主文件＋配套资源 | 报告.md + figures/架构.svg + images/封面.png | 一个版本，展开显示入口与资源 |
| 文件夹产出 | 第一版汇报/ 内有 PPT、视频、音乐、说明 | 一个版本，展开显示冻结的成员清单 |

版本形式属于版本本身；同一逻辑材料可以从单文件版演进为含资源的版本。PPT/Word 已内嵌的媒体不拆解，不解析压缩包内部资源。普通文件夹与系统把扩展名目录当作单文件的特殊包格式需区分，特殊包格式兼容性另行验收。

例如：

```text
项目/
├── 报告.md
├── figures/架构.svg
├── images/封面.png
├── 参考资料/背景说明.pdf
└── 产出/
    ├── 第一版汇报/
    │   ├── 汇报.pptx
    │   ├── media/背景音乐.mp3
    │   └── media/演示视频.mp4
    └── 第二版汇报/
        ├── 汇报.pptx
        └── media/演示视频.mp4
```

“报告”的版本只登记用户确认的 MD 与两张图片，不把同根的参考资料纳入。两版汇报可以分别选文件夹，逐版确认成员。目录不限于 refs/outputs 等固定命名，不为适配软件搬文件。

## 文件夹登记与资源发现

- 用户选择主文件、手动添加资源，或选文件夹生成候选清单；先预览纳入/排除项及数量，再确认登记。允许选项目根目录作为候选范围，但不能把根下全部文件自动认作一份产出。
- 候选清单递归读取普通文件，始终跳过内部管理目录、符号链接和不受支持项；明确显示跳过原因。excluded 文件默认不纳入，不靠目录级用途覆盖其排除状态。
- 文件夹只作为选择范围。确认后保存实际成员清单，不保存一个持续扩张的“此目录下所有文件”规则。之后新增文件是待确认的新成员，不会回填旧版。
- Markdown 本地图片链接可以给出资源候选，用户确认后归属；不能只凭 figures/images/media 名称、文件扩展名或相近时间戳自动建立关系。
- 资源建议只解析文本，不执行 Markdown 内的 HTML/脚本，不联网下载远程链接；../ 相对链接按主文件所在位置解析后仍须在授权项目根内。根内可合法解析的 ../ 链接不等于接受带 ../ 的 IPC 目标路径；规范化后走既有安全入口。根外、URL、data:、动态路径与缺失链接分别提示，不静默纳入。
- 不确定的依赖允许用户手动补充。发现建议不等于能证明完整依赖；PPT 外链媒体首版以用户确认的文件清单为准，不声称自动解析所有 Office 链接。

## 版本文件清单与历史语义（M3 目标）

Version 继续只有一个父版本，Document.currentVersionId 与跨材料 companion 关系继续绑定确切版本，不因文件夹或入口变化漂移。

每个版本登记非空成员清单；成员至少固定 fileId、项目根相对路径、登记时 SHA-256 和版本内用途（入口 / 资源 / 附件）。最多一个默认入口，入口必须在清单内；没有入口时只打开清单由用户选择。入口可选，目录不是可以传给原软件直接执行的入口。

- 旧版的成员和指纹不可被重新扫描、文件夹变化或分类修改覆盖。新登记文件生成真实指纹；不能复制主文件指纹充当整个版本的指纹。
- 修改图片、音频、视频，或增加/删除成员，即使主文件没变，也构成材料内容变化。登记新版本需要用户确认；旧版保留历史清单。
- 同一实际文件可被多个版本引用，每个版本各自保存路径和指纹。共享资源被覆盖后，分别标记受影响版本的 drift，不改旧指纹，也不强制所有引用共享资源的材料同时升级。
- 图谱仍是每版本一个节点，节点显示“1 个入口＋N 个资源/附件”，展开详情看成员；资源不是默认单独的版本节点。
- “报告配套 PPT”“演讲稿配套 PPT”仍是两个材料版本间的 companion；插图属于报告版本，是成员关系。不得混用两种关系。
- 现阶段记录清单与指纹，不承诺自动归档资源字节。旧路径被覆盖或删除后只能提示 drift/missing，不能凭哈希恢复旧内容。建议 Agent 把新版本的主文件和专属资源另存到独立版本目录，或使用不冲突的资源文件名；用户已有目录不强制迁移。
- 登记整份版本时所有成员一次性校验与提交；任一成员缺失、漂移或越界即全部拒绝，不能留下半个版本。成员数、总大小、JSON 限额需在协议实施前明确，超限须可解释，不能静默截断。

## 协议演进计划

M3 首步落地协议扩展时使用 schemaVersion=2；本次不修改 schemas、v1 fixture、业务模板和运行时类型。

实现前需完成 ADR 与正式字段定义：成员唯一性、入口约束、成员指纹、可选清单汇总指纹的规范化算法、可选文件夹范围，以及文件登记与版本快照之间的引用规则。不能直接把目录路径塞进 v1 的 fileId 或 sha256。

迁移要求：

1. 备份并校验 v1 项目，显式执行受保护迁移；只读浏览或失败不能偷偷写入新协议。
2. v1 单文件 Version 迁为仅含一个入口成员的版本。保留 projectId、documentId、versionId、fileId、原登记指纹、父版、采用、配套与导入账本；迁移不能从当前磁盘内容重算并替换旧版指纹。
3. 在用户仍使用 v1 程序时保留高版本保护；迁移失败保留可用的原文件与备份，不能部分迁移。schemaVersion、project.revision 与软件发布版本分别处理，具体 revision 规则在迁移 ADR 定义。
4. project/change/task 三套 schema、domain、IPC、校验器、fixture、业务 Agent 模板、索引/日志生成规则与测试同一兼容性改动同步更新。已有事件文件和 importedEvents 的原始摘要不改写，不自动重放历史事件。
5. M4 任务固定基础版本和所有获准读取的成员路径/指纹；M5 回交一个版本须包含其完整成员清单，不能只报主文件。旧格式事件的接受/拒绝与适配必须显式定义，不能先实现后补约定。

## 近期“全部文件”交互验收（M2）

- 默认目录视图，根下文件直接显示，子目录默认折叠；保留平铺视图切换。目录由现有安全扫描的文件相对路径构建，不新增目录读写或哈希。
- 展开与折叠均只改变展示。目录显示扫描到的后代文件数量；不把隐藏、未获权限或未扫描的文件算入，空目录暂不显示，并说明这是扫描文件的目录视图。
- 用途继续逐文件设置；目录行只展示和展开，不提供会暗示整目录同一用途的控件。
- 搜索按完整相对路径匹配，展示命中文件和祖先路径；不匹配同级文件不展示。搜索期间临时展开祖先，清除后恢复原折叠状态；有“没有匹配文件”状态。显示总文件数与匹配数。
- 刷新尽量保留仍存在的目录展开状态；切换项目重置，避免目录状态或异步结果串到另一个项目。视图偏好留在界面/应用设置，不写 project.json。
- 折叠不触发分类写入，不改稳定 ID、指纹、revision 或成员归属。尚未实现成员归属时，不能仅凭目录名隐藏图片或显示“已归属某材料”。
- 键盘可聚焦展开按钮，Enter/Space 可切换，aria-expanded 正确；隐藏行不进入焦点序列。优先用现有 HTML 表格与展开按钮，无需未完整实现的 ARIA treegrid。
