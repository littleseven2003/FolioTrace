# 产品范围 · MVP 0.1

## 用户与核心问题

个人及小团队使用 Agent 写 Word、PPT、Markdown 等材料；项目根目录混有参考资料、过程文件、历史版本和不参与编写的资料。目标是看清使用边界、版本演变与材料配套关系，继续沿用外部 Agent 编写习惯。

## 术语

- 文件 File：磁盘上的普通文件，有相对路径、用途与指纹；物理目录是浏览容器，不自动成为材料。
- 材料 Document：逻辑文稿，例如“汇报 PPT”，包含多个版本。
- 版本 Version：某材料的一次内容登记，至多一个父版本。当前 v1 绑定单文件 SHA-256；M3 目标扩展为单文件、主文件＋资源或文件夹成员清单，具体边界见 [材料与配套资源设计](10-material-bundles.md)。
- 配套关系 Relation：两个具体版本间有向的 companion 关系；不是 Git merge。
- 当前采用 currentVersionId：每份材料由用户指定；允许为空。
- 任务 Task：指定基础版本、参考快照与要求的写作交接单。

## MVP 功能与验收

| ID | 功能 | 最小验收 |
| --- | --- | --- |
| P01 | 接入现有文件夹 | 不移动文件；扫描结果可逐项或批量指定用途 |
| P02 | 文件分类 | reference / process / output / excluded / unclassified；未分类不默认参考 |
| P03 | 材料版本 | 建立逻辑材料；单文件、主文件＋资源、文件夹成员清单均按一个版本登记；确认入口与成员、选择父版；时间戳只能给建议（多文件待 M3 协议升级） |
| P04 | 当前采用 | 用户显式确认切换；新版本自动导入仍为候选 |
| P05 | 时间线与总览 | 每材料稳定颜色、每版本一个节点；实线父子、虚线配套 |
| P06 | 写作任务 | 指定版本、资料、要求、是否同步配套，保存任务并复制指令 |
| P07 | Agent 回交 | 校验独立 JSON 记录，完整记录入库；缺项进入待处理 |
| P08 | 自动索引 | 从 project.json 生成 PROJECT_INDEX.md 与 CHANGELOG.md |
| P09 | 文件变化 | 重命名、丢失、原地修改、未登记文件提示，不静默修补历史 |
| P10 | 外观 | 4 背景、4 强调色、背景浓度、动画开关、减少动态效果 |
| P11 | 原软件打开 | 仅打开已登记且允许的文档类型；失败时反馈路径和原因 |

## 不做

云同步、团队实时编辑、内置模型调用、Agent 进程调度、Office 正文编辑、正文 diff、自动合并、自动发布、跨项目关系、任意脚本执行。首版不移动业务文件，不自动删除文档。不自动为业务项目建立 Git 仓库。

## 规则

“旧版本”是版本状态而不是文件角色。参考文件也可能更新；任务保留读取时的内容指纹。多材料按逻辑文稿分组，不按扩展名粗暴合并。PPT/报告/演讲稿的配套绑定到确切 versionId。

## 材料与资源边界

用途、文件类型和版本归属独立。配套资源不是第六种用途；目录可混合多种用途。Markdown 插图和 PPT 外置音视频可属于版本成员，资源变化也构成内容变化；完整内嵌资源的 Office 文件继续按单文件登记。先预览确认归属，不能按 images/figures/media 名称自动推断。成员关系区别于 PPT/报告/演讲稿之间的 companion。完整约定见 [材料与配套资源设计](10-material-bundles.md)，当前 v1 尚不支持成员清单。

## 产品状态

文件：正常 / 丢失 / 内容漂移。变更回交：待检查 / 待修正 / 已导入。任务：待产出 / 已有产出 / 已确认 / 已取消，不显示无法核实的“Agent 正在执行”。新版本不自动继承上一版的配套关系。

## 发布标准

用户可从一个合成项目生成任务、由外部 Agent 回交新版、在图中查看关联并确认采用，重启后状态一致。与 README 中支持的平台声明一致，不把仅在 macOS 验证的包宣称跨平台稳定。
