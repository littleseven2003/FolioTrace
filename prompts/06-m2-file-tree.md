# M2 下一小步：全部文件目录视图

在现有 feat/m2-project-files 分支继续。先读取根 AGENTS.md、docs/STATUS.md、docs/02-ux.md、docs/10-material-bundles.md、docs/06-testing.md；检查工作区，尊重已有改动。用户已完成 M2 初始化、分类保存、重新扫描及退出重开同目录的测试；这是用户验收，不记为 Agent 自己执行的测试。

## 本轮唯一目标

解决 images、figures、media 等目录的大量资源在全部文件页平铺刷屏的问题。实现展示层目录浏览，不登记多文件版本、不改变 schema 或扫描权限。

1. 从现有扫描结果的相对文件路径构建目录树；默认目录视图，子目录初始折叠，根下文件直接显示，保留平铺切换。目录显示扫描到的后代文件数，空目录暂不显示。不得为展示额外读取目录、改扫描忽略规则、计算哈希或跟随符号链接。
2. 用途继续逐文件设置；目录仅为容器，不设目录用途、不批量继承、不凭 images/figures/media 名称自动排除、隐藏或建立材料归属。保持现有用途值、保存、初始化、重新读取、冲突提示和扫描警告。
3. 搜索按完整相对路径匹配，显示匹配文件和祖先路径；搜索期间临时展开祖先，清空后恢复先前展开状态。显示总文件数与匹配数，支持无匹配状态。
4. 刷新保留仍存在目录的展开状态；项目改变时重置状态，视图切换不得发起分类写入。视图状态不写 project.json。
5. 优先沿用表格、按钮和现有样式；展开按钮有 aria-expanded 和可见焦点，Enter/Space 可操作。长中文路径可读，隐藏行不能进入焦点序列；无需引入新组件依赖或实现不完整的 ARIA treegrid。

## 验证

用合成扫描结果覆盖：根下 Markdown＋多层图片/音视频、同名不同路径文件、混合用途、折叠/展开、平铺切换、搜索/清空、刷新与新增文件、空/无匹配、键盘与 aria-expanded。

在交互测试确认折叠/搜索/切换视图不会调用分类写接口，展开后用途仍正确且保存可用。检查分类服务、初始化、IPC、根目录保护的已有回归测试继续通过。

本轮不增加批量分类、重命名迁移、最近项目自动恢复或 v2 协议；多文件版本按 docs/10-material-bundles.md 留给 M3。

每个完成且验证的小改动立即 commit，标题为“英文类型：中文描述”，仅暂存本轮文件。运行 npm run check、git diff --check，更新 STATUS/CHANGELOG 的实际结果。保持 MIT、软件版本 0.0.0、schemaVersion=1。推送当前分支，更新 Draft PR #3 的范围与验证结果，核对最新 head 的 CI；本轮不自动合并。最终报告完成点、提交、检查、未完成项和 PR 链接。
